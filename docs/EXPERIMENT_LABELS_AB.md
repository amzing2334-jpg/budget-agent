# 第四轮：固定版本标注的 A/B（非劣性）

本协议在运行前冻结，写于 2026-11-11，第三轮尚未出结果。运行后只追加结果，不修改下面的判据。

## 问题

PR #29 新增 `revision_labels = "fixed"`：事件头在记录时就固定下来，历史在窗口滑动之前只追加不改写。它的收益是推理时的前缀缓存和训练时的打包效率更高。按第三轮前 4 步估算，打包的节省会从 3.06 倍提高到约 5.2 倍（`docs/PREFIX_PACKING.md`）。

代价可能是 agent 能力下降：旧事件不再显式标为 stale，模型要自己比较版本号。本轮回答：**固定标注是否让通过率明显变差？**

## 设置

- **策略**：第一轮 SFT 学生（合并后的 1.5B），两种模式用同一个策略。
- **harness**：加固后的配置 `configs/swesmith-vllm-tokens.toml`，以及已迁移的任务清单（按题测试时限、4096 MB 命令内存上限、28,672 token 的上下文预算）。
- **两个评测池**：
  - `relabel`（默认）；
  - `fixed`（`--set revision_labels=fixed`）。
- **采样**：留出集 96 题，每个池每题采样 8 次，temperature 0.7。
- **记录**：两个池都开启 `api_logprobs`，为了能统计打包效果。它只影响记录，不改变采样。
- **前缀缓存**：每个池启动前重启 vLLM，让前缀缓存从冷启动开始；在池的前后各读一次 vLLM 计数。
- **运行方式**：`scripts/autodl/round4_labels_ab.sh`。

## 判据（冻结）

- **主指标**：留出集 pass@1，`fixed` 减 `relabel`，按题配对 bootstrap（10,000 次重采样），计算 95% 置信区间。
- **决策规则（非劣性界限为 2 个百分点）**：
  - 区间下界 ≥ −2.0 个百分点：判定固定标注不劣于重新标注，此后的配置默认采用 `fixed`；
  - 否则保持 `relabel`。
- **防作弊检查**：逐条检查两个池中通过的补丁。
- **次要指标**（只做描述）：
  - 前缀缓存命中率；
  - 每次尝试处理的 prompt token 数；
  - 每个池的 rollout 用时；
  - 两个池上打包训练的 token 节省（`bench_turn_packing.py`）；
  - 状态分布；
  - `edit_file` 成功率。

## 预算

两个评测池各约 51 分钟，加上两次启动 vLLM，合计约 1.8 GPU 小时，约 6 元。

## 已知局限

- 只测了一个策略，而且这个策略是在重新标注的历史上训练出来的，所以本轮测的是"换标注方式的分布偏移"会带来多少损失。
- 如果固定标注被采用，之后在它上面训练的策略可能表现不同。
- 1 个种子，4 个留出仓库。

## 追加：第四轮结果（运行于 2026-11-11 19:24–21:37 UTC）

运行的代码是 commit `a3b46f8`，部署时核对的代码树哈希为 `0a056a8b0c7d0529`，运行结束后去掉 `__pycache__` 再算一次，结果相同。原始输出在 [`docs/data/round4/`](data/round4/)。

- **打包的预测得到验证**：在 `relabel` 池上，按"把重新标注造成的断点去掉"估计的节省是 4.43 倍，`fixed` 池实测 4.48 倍。`fixed` 池中 712 次历史断点全部来自窗口滑动或重建，没有一次来自重新标注；`relabel` 池中 2,104 次历史断点里有 1,362 次只是重新标注。
- **推理侧**：前缀缓存命中率提高 5.8 个百分点，每次尝试的模型用时从 17 秒降到 12 秒；但每次尝试的总用时没有下降，评测池总用时反而多了 2.6 分钟。32 个 worker 下，评测 rollout 的瓶颈已经不在模型一侧。
- **按仓库**（每个仓库 192 次）：funcy 14 对 15，parse 17 对 11，tinydb 20 对 19，tomli 2 对 0。
- **被限制终止的命令**（`limit_events.jsonl`）：`relabel` 共 1,777 条命令，2 条触到测试时限，1 条 MemoryError，verifier 超时 0 次；`fixed` 共 1,797 条，3 条触到测试时限，0 条 MemoryError，verifier 超时 1 次。

**费用。** GPU 2.09 小时（各阶段合计），约 6.9 元。

**解读与下一步。**
- 固定标注在效率上兑现了预期：打包节省从 2.86 倍提高到 4.48 倍，前缀缓存命中率提高 5.8 个百分点。
- 但通过率的点估计低了 1.04 个百分点，区间允许最多约 3 个百分点的损失，非劣性没有得到证明。这个策略是在重新标注的历史上训练出来的，本轮测到的是换标注方式造成的分布偏移，而不是固定标注本身对能力的影响（协议中的已知局限）。
- 更公平的检验是让策略从 SFT 起就在固定标注的历史上训练：把 SFT 数据按固定标注重新渲染，重训 SFT 学生，再做同样的 A/B。这一步留到第五轮之后。
