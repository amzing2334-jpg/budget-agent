# 复现评测：第二轮 GRPO 的提升是否稳定

本协议在运行前冻结，写于 2026-11-11。运行后只追加结果，不修改下面的判据。

## 问题

第二轮的冻结结论是"提升"：留出集 pass@1 从 6.25% 升到 9.64%，但 95% 置信区间是 [+0.26, +7.03] 个百分点，下界离 0 很近。两组数字各来自一次评测。这里要回答两个问题：

1. 同一个策略在同样的配置下重新评测，pass@1 会波动多少（评测噪声）？
2. 在一次独立的新评测里，GRPO 策略是否仍然优于 SFT 学生？

## 设置

两个策略：
- **SFT 学生**：第一轮合并后的模型，与第一轮相同，由 vLLM 直接服务；
- **GRPO 策略**：第二轮的 adapter v12，与第二轮相同，以 LoRA 形式加载在 SFT 合并模型上（`--lora-modules`）。

评测设置与第一、二轮完全相同：
- 留出集：funcy、tomli、parse、tinydb，共 96 题，每题采样 4 次。
- 配置：`configs/swesmith-vllm.toml`，即 temperature 0.7、`recent` 策略、最多 30 步、字节预算 80,000。
- 任务清单：用第一、二轮所用的原始清单（`eval.round1.jsonl`，没有按题超时字段），所以命令和 verifier 的上限仍然是统一的 300 秒。verifier 超时记为失败，与第二轮相同。
- 代码版本：评测行为与第二轮相同；之后合并的改动只在启用新配置或任务清单带新字段时才生效。

## 判据（冻结）

- **主指标**：本次复现中，GRPO 策略减 SFT 学生的留出集 pass@1，按题配对 bootstrap（10,000 次重采样），计算 95% 置信区间。规则与前两轮相同：
  - 下界大于 0，结论为"提升复现"；
  - 区间包含 0，结论为"提升未复现"；
  - 上界小于 0，结论为"反向"。
- **次要指标**（只做描述）：
  - **评测噪声**：同一策略两次评测之差。SFT 学生对比第一轮的评测池，GRPO 策略对比第二轮的评测池，各自做配对 bootstrap。
  - **合并估计**：每个策略把原始评测和复现评测合起来，每题 8 次采样，再做 GRPO 对比 SFT 的配对比较。
  - 逐条检查通过的补丁，另外报告剔除可疑样本后的结果。
- **据此决定下一步**（同样预先写定）：
  - 如果"提升复现"，下一轮在改进后的 harness 上扩大 GRPO：启用按题超时和按真实 token 的预算，训练更多步；
  - 否则，不把第二轮的提升当作能力结论，下一轮先降低每步的训练成本、增加步数，再重新评估。

## 预算

两次评测各约 31 分钟，加上两次启动 vLLM，合计约 1.1 GPU 小时，约 3.6 元（A100，3.28 元/小时）。

## 已知局限

- 每个策略只加一次复现，评测噪声的估计也只有一个样本。
- 复现评测与原始评测使用同一批题目，只能估计采样带来的噪声，估计不了题目抽样带来的噪声。
