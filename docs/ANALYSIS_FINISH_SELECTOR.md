# 离线分析：用 agent 自己的主动结束挑选尝试

本协议在计算之前冻结，写于 2026-11-13 04:20 UTC。本分析不需要 GPU，只用已经完成的评测池的台账（`attempts.jsonl`）；写定时还没有按下面的规则计算过任何池子。运行后只追加结果，不修改下面的判据。

## 问题

留出集评测每题采样 8 次。实际使用时，如果能从这 8 次里挑一个提交，又没有隐藏测试可用，能不能只靠 agent 自己的信号挑？最直接的信号是它有没有主动结束（调用 `finish`）。各轮记录已经报告过主动结束时确实修好的比例（55% 到 100%），远高于 pass@1，所以方向基本可以预期；本分析量化的是按题挑选之后的净效果，包括没有任何一次主动结束的题。

本分析回答：**每题采样 8 次、按"主动结束优先"挑一个尝试时，期望成功率比随机挑一个（pass@1）高多少？**

## 规则（冻结）

- **选择器**：对每道题，如果至少有一次尝试以 `finished` 结束，就在这些尝试中均匀随机挑一个；否则在全部评上分的尝试中均匀随机挑一个。只用这个信号，没有其他排序或打破平局的规则。
- **每道题的期望成功率**：被挑选的那组尝试中修好的比例。随机挑一个的期望成功率就是这道题的通过率（与 `compare_pools.py` 的 pass@1 相同，未评分的尝试不计入）。
- **主指标**：第十轮的评测池（目前最好的策略，96 题 × 8 次）上，选择器的期望成功率减 pass@1，在题目上平均；按题配对 bootstrap（10,000 次重采样，种子 0，与 `compare_pools.py` 相同），计算 95% 置信区间。
  - 下界大于 0，结论为"主动结束是有用的挑选信号"；
  - 区间包含 0，结论为"未检测到收益"；
  - 上界小于 0，结论为"按主动结束挑选有害"。
- **次要指标**（只做描述）：
  - 同样的计算用于 SFT 学生（第四轮 `relabel` 池）和第五、七、八、九轮的评测池；
  - 参考上限：任意一次修好就算成功（pass@8）；
  - 没有任何一次主动结束的题数，以及选择器挑中的尝试中修好的比例。
