# 实验协议

本项目用于比较代码修复过程中不同上下文管理方法。内置小任务与脚本模型只能验证软件流程，不能证明 LLM 能力、SWE-bench 分数或策略优劣。

## 固定条件

比较 full、recent、summary、structured 时，固定模型与服务版本、提示、任务集合、输入/输出预算、最大步数、工具权限、执行环境、温度和重复标签。上下文窗口限制与单任务累计推理预算是两个不同限制。摘要模型调用也计入累计输入/输出量和费用。provider 返回的 token 用量与本地估计必须标注；字节计数不是模型真实 tokenizer。full 是本项目自己的不压缩执行器基线，不代表已经复现或比较 mini-swe-agent 原版。

默认以输入加输出 token 为累计预算。价格由用户显式填写，缺省费用为未知，不能当作零。缓存折扣、隐藏推理 token、供应商计费口径需要核对后再讨论实际经济收益。配置中的 seed 当前仅作本地重复标签，不会传给模型 API，不提供采样可重现保证。报告按供应商实际返回的模型名称分组，避免请求别名漂移后仍被当作同一模型。

Transformers 后端是上述 API seed 说明的例外：每次任务/策略开始时重置 PyTorch RNG，但不承诺跨硬件确定性。它用同一固定版本的 tokenizer/chat template 编码计数与推理；结果记录模型和生成配置、代码指纹以及实际容器 image ID。SWE 镜像可能包含任务 base_commit 之后的安装用提交；核实祖先关系，记录任务版本和镜像实际 HEAD，并以镜像初始 HEAD 为补丁差分起点。这样 Agent 与官方评分保留相同的安装调整，这些调整不进入 Agent 补丁。本轮固定官方配方中的额外源码调整仅为 pyproject 的 setuptools 约束，仍需运行评分对照核验。

## 2026-10-22 云端开发诊断约定

本轮检验问题是“真实模型是否能走完工具调用、生成补丁和独立评分链路”，还不检验上下文策略的统计优势。先在自建 slugify 题做协议验证，再使用原有开发清单的第一题 `astropy__astropy-12907`；选择发生在查看本轮模型结果之前。该题只能作为 dev，不进入最终独立测试。

模型为固定 commit 的 Qwen2.5-Coder-7B-Instruct，配置见 `configs/cloud-qwen7b.toml`：8,192 上下文、32,000 累计输入加输出 token、最多 20 步、单次输出 768 token、温度 0。主要诊断对照为 recent 与 structured。若继续加入 summary，必须使用相同配置、题目和一次尝试，摘要开销全部入账。原始失败与重试都保留，修复代码后必须换新输出目录并记录变更。

本次单卡 RTX 4090 按已授权的 1.87 元/小时计费，原定 2026-10-22 01:34（北京时间）释放实例，不能为等待实验而自行延期。准备环境、下载和验证均计入租卡时间。仅在云端进行模型计算，本机只编辑文件和运行 CPU 软件测试。

若官方预构建镜像无法拉取，允许从固定版本的官方 Dockerfile 重建同一任务环境，记录配方来源、摘要和实际 image ID。重建镜像不能宣称与官方镜像字节相同；先做标准补丁与无修复补丁的评分正负对照。标准补丁与隐藏测试留在独立评分目录，不进入 Agent 工作区、任务清单或提示。

## 任务与结果

先用开发任务调试，再冻结评测任务清单。不得按改进方法是否成功筛选任务；环境无法运行的情况单独记录，不静默丢弃。最终测试任务不用于调整提示与策略。公开基准可能存在预训练污染，项目结果只支持指定模型与子集上的结论。

本地任务的隐藏校验位于 agent 工作目录之外，由最终评测执行。host-local 模式不是安全沙箱，模型运行 shell 命令时可访问主机，因此正式模型实验应使用 Docker。容器测试与宿主 smoke 测试的验证强度不同。

SWE-bench 导入只保留 problem_statement、仓库版本信息和环境标识。标准补丁、test_patch、FAIL_TO_PASS/PASS_TO_PASS 和 hints_text 不进入 Agent 任务清单。生成 patch 后交由官方 harness 在独立环境评测。run_evaluation 的 run_id 每次使用新值，避免重用旧结果缓存。导入官方分数前验证官方 patch.diff 与本项目补丁一致。

## 指标与比较

- 同时报告 attempted、graded、success。未评测项显示 ungraded；存在未评测项时不显示完整成功率。
- 报告全部尝试的总费用、token 数、耗时；单位成功费用 = 全部尝试总费用 / 成功数，包含失败花费。
- 不同模型、预算、split、计量方式分组展示；任务 ID、任务指纹和重复标签集合不匹配时明确标记不可作受控比较。
- 实际用量超过预算预留或用量未知的尝试仍保留在记录中；其所在策略不显示成功率，组内不作有效的固定预算比较。通过补丁测试不能消除预算违规。
- 失败分析包括上下文超限、总预算耗尽、无效动作、工具失败、重复探索、旧证据失效、补丁未通过测试。
- 先确认任务可以成功运行，再扩大到固定评测子集；不能用三五个任务宣称普遍提升。
- 对关键比较重复运行；同一任务的重复结果存在相关性，不能将其当作独立新任务计算置信区间。

## 当前研究定位

结构化记忆与上下文压缩已有大量先行工作。首版交付工程实现、受控实验与可审计结果，不宣称算法创新。只有实际完成模型训练及独立评测后，才可在简历中使用 SFT、后训练或 Agentic RL 等表述。
