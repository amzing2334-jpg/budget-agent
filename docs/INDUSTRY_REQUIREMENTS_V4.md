核查日期：2026-10-22。本文回答“相关岗位到底在招什么能力，以及我们应拿出什么项目证据”。它不是职位数量统计，也不是录用概率预测。

## 本次最重要的新证据

比上一轮泛化的 Agent 岗位更直接的证据，是百度的两项 Coding 专岗：**Coding Agent 策略算法实习生 J96208** 和 **代码智能体大模型架构实习生 J101404**。前者直接要求工具决策、上下文、错误恢复、成本和实验对照；后者直接涉及隔离环境、轨迹数据、训练与推理基础设施。它们说明，一个能处理真实仓库任务、分析失败并验证具体改进的项目，确实对应招聘方公开描述的工作。

这不表示已有项目达到岗位标准。目前的单题失败诊断支持我们调整开发顺序，尚不能证明修复能力、上下文收益或后训练能力。

## 如何解释证据

- **A：官方正文直接可读。** 能核实正文与页面标注，但不保证仍有招聘名额，也没有验证申请入口提交成功。
- **B：官方 URL 的搜索索引可读。** 本轮直接打开仅返回登录或空壳；可引用已索引职责，不能当成实时完整岗位页。不会用第三方转载补齐缺失要求。
- **C：仅核实标题、入口或产品资料。** 不据此生成具体招聘要求。
- 发布或更新日期均按页面原文；检索日期、抓取日期不冒充发布日。未找到具体岗位与确认该公司没有岗位，是不同结论。

## 对“大厂需要什么样的 Coding Agent”的判断

以下是结合上述官方工作描述作出的综合判断，不是某一家公司的统一招聘政策。

**它需要在真实研发环境里交付可验证的工作。** 研究原型应至少能完成“理解 issue—定位代码—提出修改—运行合适检查—依据反馈继续—提交补丁”的闭环。企业产品还会延伸到需求、评审、部署与协作。我们的近期目标应选择仓库修复这一条完整路径，优先让输出可执行、可检查、可复盘。

**模型、Agent 运行时与评测要能分开分析。** 模型可能不会使用工具；接口可能使模型误读观察；上下文可能丢失必要信息；执行环境也可能失败。若这些因素同时改变，只能证明一个整体配置不同，不能知道哪项设计有效。当前 v3B 重复歧义编辑的轨迹，正适合先做模型与交互协议的短对照。

**可控性需要落在具体行为上。** 例如编辑歧义能否被识别、模型能否获得可操作的错误反馈、测试证据是否属于当前代码版本、结束时是否真实产生交付物。不能以增加几个策略名称、多个角色或一个聊天界面作为这些能力已经存在的证据。

**研发效率需要同时包含质量与成本。** 修复成功、引入回归、无补丁结束、耗尽预算和基础设施异常应分别记录。延迟、token、模型调用与机器费用要有清楚口径。降低 token 但无法交付，不自动构成有效提效；提高通过率但无边界增加采样，也不自动说明策略更好。

**后训练的价值取决于数据、环境和评测的闭环。** 可复用的轨迹、正确的奖励、错误分类与独立任务评估，是后训练工作的基础。项目可以先证明这些基础能力，再选择有学习信号的问题做 SFT 或 RL。企业所需的大规模跨 harness 合成、异步 rollout 和分布式训练，是后续成长方向，当前不应伪装已经实现。

## 当前学生条件与岗位选择

就现有信息——计算机硕士、网络协议研究背景、Python/PyTorch 基础较弱、年底可开始、可实习 3–6 个月——本轮证据支持的排序是：

1. **优先准备 Coding Agent 策略、评测与执行系统实习。** 这与已在建设的工具交互、错误恢复、预算和真实任务评测直接相连，有机会用可检查的工程与实验补足跨方向经历。
2. **将轨迹数据与训练/推理系统作为下一层。** 要补齐深度学习、模型服务、显存/吞吐与数据处理知识。J101404 的六个月条件要提前核对；只能实习三个月时不能假设符合。
3. **将核心 Agentic RL/基础模型研究作为更高门槛目标。** 需要实际理解并验证训练算法、数据和模型行为。本轮职位证据没有支持“只做一个项目便能直接进入基础模型核心研究”的判断。

本科院校信息不能从上述公开 JD 推导为必然淘汰或必然录取。能否稳定到岗、毕业资格、编程与算法基础、项目承担的实际工作，都是需要分别确认的因素。
