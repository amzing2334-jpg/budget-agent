# 第九轮：失稳检测保留的 adapter（第七轮的 v26）

本协议在运行前冻结，写于 2026-11-12 16:40 UTC。此时第七轮的结果已经写入记录，第八轮正在训练（第 3 步）；本轮不训练，只评测一个已经保存的 adapter，设计不依赖第八轮。运行后只追加结果，不修改下面的判据。

## 问题

第七轮在第五轮的 adapter（v29）上继续训练 46 步，最后的 adapter（v46）在留出集上没有可检测的提升，而且第 36 步以后训练失稳：无效动作的比例从约 1% 升到 74% 到 83%，训练题上的通过率始终不变。只评测了 v46，所以还不知道失稳之前的继续训练有没有用。

PR #72 加入的失稳检测在每批 rollout 结束时检查无效动作的比例：连续 2 批超过 4% 就停止训练，保留最后一个比例不超过 4% 的策略。把这条规则用在第七轮每步的 rollout 上，它会在第 28 步停止（第 27、28 步分别为 5.5% 和 6.3%），保留 v26（第 26 步为 2.2%）。

本轮回答：**失稳检测保留的 adapter（第七轮的 v26）在留出集上是否比第五轮的 v29 好？** 也就是说，如果第七轮当时带着这条规则运行，继续训练能不能带来提升。

## 设置

- **评测的 adapter**：`outputs/round7/grpo/adapters/v26`，即第五轮的 v29 再经过 26 步训练（种子 2）。驱动脚本先用 `rollout_health` 和 `HealthGuard` 从第七轮各步的原始 rollout 重新计算规则的选择，结果不是 v26 就拒绝运行。
- **规则的来源**：界限（4%）和连续批数（2）是在看过第七轮的训练曲线之后、在留出集上评测任何中间 adapter 之前定下的，依据只有训练时的数据：第五轮评测中无效动作占 1.6%，第七轮前 27 步不超过 2.4%。界限取 2% 会保留 v25，取 10% 会保留 v32。
- 不训练；基础模型和服务配置与第五、七轮的评测相同。

## 评测

- 留出集 96 题，每题采样 8 次，temperature 0.7，重新标注，同一 harness 和配置。
- **基线**：第五轮的 GRPO 评测池（v29，每题 8 次），不重新评测。
- 运行方式：`scripts/autodl/round9_eval.sh`，没有参数。

## 判据（冻结）

- **主指标**：留出集 pass@1，v26 减第五轮的 v29，按题配对 bootstrap（10,000 次重采样），计算 95% 置信区间。
  - 下界大于 0，结论为"失稳之前的继续训练有提升"；
  - 区间包含 0，结论为"未检测到提升"；
  - 上界小于 0，结论为"变差"。
- **防作弊检查**：逐条检查通过的补丁，另外报告剔除可疑样本后的结果。
- **预先登记的次要指标**（只做描述）：
  - 对第七轮最后的 adapter（v46）和对 SFT 学生（第四轮 `relabel` 池）的差值；
  - 对照注入 bug 之前的源码和隐藏行为检查，报告没有恢复原有行为的补丁占比，以及把它们算作失败后的敏感性比较；
  - 无效动作比例、每次尝试的输出 token、状态分布、工具使用、被限制终止的命令数。

## 预算

一次每题 8 次的评测（约 1.3 小时，第五轮为 4,841 秒）加一次启动 vLLM，约 1.5 GPU 小时。

## 已知局限

- 规则是事后定的：界限的选择看过第七轮的训练曲线（没有看过任何中间 adapter 的留出集结果），只评测一个 adapter。
- 第七轮只有 1 个种子；训练题只有 33 道，与 SFT 数据的题重合；4 个留出仓库，bug 是合成的。
- 即使 v26 更好，也只说明这一次运行里失稳之前的训练有用，不说明多长的训练最合适。
