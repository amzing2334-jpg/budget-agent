# 有界源码保留：设计、验证与证据边界

观察日期：2026-10-27（北京时间）。本轮从上一轮的可见性审计继续：三条真实 `mask` 轨迹中的重复获取，不能通过“历史读过就停止”的判据解决。

## 问题与候选方法

已有 mask 保留全部动作和来源标记，但只保留最近两条完整工具观察。历史序列读完源码 1–317 行后，又分别获取 50–110、290–317、200–220 等范围；这些旧行当时已经被隐藏。此证据支持研究保留方式，不足以证明更多源码一定更利于模型修复。

新增可选策略 `mask-read`，默认策略和已有 mask 不变。它在原 mask 输入上保留少量旧源码：

- 完整任务、全部原始动作、全部事件来源、最近两条完整观察保持原样。
- 仅从**当前连续工作区 revision 段**中的成功、可解析且未截断的 `read_file` 输出选择源码；A→B→A 回退不会恢复第一次 A 的缓存。
- 优先更新的读取，再选择完整行前缀；按照实际返回的 canonical path 和行号去重。只给实际显示的行记可见覆盖；若不同观察在同 revision 下出现内容冲突，更新内容优先。
- 旧观察替换为明确的 `read_file excerpt`，记录 path、source_event_id 和 retained_lines。保留原事件位置及 provenance，不伪装成完整原始读取区间。
- `read_memory_tokens` 默认 1024，表示相对原 mask 的**完整消息输入增量上限**，包含元数据与标记；同时服从本次剩余输入上限。设为 0 时请求与 mask 严格相同。
- 原始事件不会改写，没有摘要调用或额外模型请求。新内容照常进入统一输入输出预算；不能用所谓免费记忆绕过总额度。

若基础 mask 已超限，候选策略同样明确失败。额度不够保留一整行时保持该观察被屏蔽，不截断源代码行。未保留的原始内容仍可通过 recall 读取。

这是一种简单的可检验启发式：它不理解源码语义，也不保证最新读取或行前缀最重要。默认 1024 不是通过评测选出的最优值。保留更多源码会在后续请求中重复收费，可能使总预算更早耗尽。

```bash
python -m pytest -q
```

输出必须使用新目录。回放只重建每条历史调用之前的上下文，不调用模型，不重新执行工具，也不运行训练。

独立用例覆盖：额度为 0；完整消息增量；当前 cap；整行裁剪；路径/内容去重；最近两条观察保持不变；跨 revision 及回退；旧格式、截断与失败读取；原始事件不变；chat/transcript；与可见读取控制器的兼容；scripted runner 的实际预算对账。

39 个前缀均能构造两种请求，0 个超限。平均额外输入为 **706.15 个分析 token / 前缀**，单前缀最大 1024。这里的 464 是跨前缀重复统计的行出现次数，不是 464 条独立源码，也不是 464 个评测样本；三条历史只有同一个 task ID。

候选仍遗漏 238 次已知目标行出现。另有 **15 个前缀增加输入，但没有增加下一步目标读取的可见覆盖**，其中包括下一步并非读取的调用。这只说明当前覆盖指标没有记录到增益，不能据此判定保留内容对其他动作无用。有限额度、按新近度选择及完整行前缀都是可能的限制；本轮没有逐项归因或调参，不能把它们写成已证实的唯一原因。

判定：通过软件与回放验收，作为**可选实验策略**保留，暂不替换默认策略。不继续从这道反复使用的开发题中调出“最佳”额度，也不把覆盖变化包装成效率或修复率收益。下一项关键证据必须来自真实模型和独立评分。

## 前缀回放的含义

构造策略只使用当前调用之前的事件。调用后读到的目标源码只用于**事后**测量目标中哪些已知行在这次请求中可见，不能用于选择保留内容。

回放中使用明确的分析计数器。`tiktoken:cl100k_base` 不是这些 Qwen 运行的原 tokenizer，消息 framing 也只是估算；所有数字必须标为分析编码下的输入估计，不能作为供应商费用或原模型精确 token。固定历史前缀的求和不等于新策略真实运行消耗，因为模型下一步动作、停止时间与后续预算都会变化。

结果需要同时展示额外输入成本、目标已知源码的可见性和超限前缀，不能只挑覆盖增加的部分。三条 mask 历史均来自同一道已知开发题，不是三道独立任务。recent 和外部 mini-SWE 等非 mask 记录应说明排除原因。

## 后续真实对照

先得到能产生有效独立修复的参考配置，再冻结多个开发任务和资源条件。候选与 mask/recent 比较时，模型版本、任务、总预算、镜像、CPU/RAM、超时、采样和 decision policy 相同，并固定 `loop_policy=off`，避免“可见性改变”和“提前停止改变”同时影响结果。

云端命令示例（此轮不执行）：

```bash
python -m budget_agent compare --config configs/cloud-v5-qwen3-mask.toml --tasks tasks/swebench-pilot.jsonl --strategies mask mask-read --read-memory-tokens 1024 --loop-policy off --output runs/new-model-memory-pair
```

上述模型是保留的旧诊断配置，不表示应该继续重复旧题。真实结果必须包含非空补丁、独立评分、所有失败、token/耗时，以及没有改善或代价过高的情况。还应增加更大近期窗口的简单对照，区分收益来自保留选择还是单纯更多可见源码。

当前没有新的真实模型轨迹，因此不能声称修复率提高、真实重读减少、API/GPU 成本降低或 RL 能力增加。
